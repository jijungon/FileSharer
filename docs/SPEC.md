# FileSharer — 요구사항 · 기능 명세서

> 이 문서의 목적은 **이 서비스를 다른 곳에서 다시 만들 수 있을 만큼** 요구사항·기능·규칙·결정을 남기는 것이다.
> 기능 목록은 코드를 읽으면 알 수 있지만 **"왜 그렇게 했는지"** 는 문서가 아니면 사라진다. 그래서 8장(결정 기록)이 이 문서의 핵심이다.
>
> 기준 버전: **v1.0.0** · 최종 갱신: 2026-09-28

---

## 1. 개요

### 1.1 무엇인가

사내 구성원이 **파일을 올리고, 찾고, 브라우저에서 바로 읽고 편집하고, 링크로 공유**하는 웹 서비스.
단순 파일 저장소가 아니라 **마크다운/코드 뷰어 겸 에디터**를 내장한 점이 핵심 차별점이다.

### 1.2 사용자와 접근 경로

| 대상 | 접근 방법 | 할 수 있는 것 |
|---|---|---|
| 사내 구성원 | Google 로그인(도메인 제한) 또는 로컬 계정 | 전부 |
| 관리자 | 위 + `admin` 역할 | 사용자·팀 관리, 디스크·감사 로그 |
| 외부(비로그인) | 공유 링크(`/s/<token>`)만 | 그 링크의 파일만 미리보기·다운로드 |
| 서버·CI(무인) | API 토큰(`fsk_…`) | **업로드만** |

### 1.3 형태와 배포

- **단일 컨테이너**: SPA와 API가 **같은 오리진**에서 서빙된다(프런트 빌드 결과를 백엔드가 정적 서빙).
- **상태는 한 곳**: SQLite 파일 + 블롭 스토리지(local 또는 R2). 볼륨 하나만 백업하면 된다.
- **pull형 자동 배포**: CI가 이미지를 GHCR `:latest`로 올리면 서버의 watchtower가 약 60초 폴링으로 교체한다. 서버에 배포 권한(SSH/CI 키)을 주지 않아도 된다.
- **머지와 배포를 가른다.** 머지해도 나가지 않고, **태그를 밀어야** 나간다.

  | 무엇 | 언제 | 버전 | 이미지 태그 | 배포 |
  |---|---|---|---|---|
  | 머지 | main 에 머지 | `v0.0.<빌드>` | `:b<빌드>` · `:<sha>` | **안 됨** |
  | **dev 배포** | `v0.*` 태그를 민다 | 태그 그대로 | `:latest` · `:<태그>` · `:<sha>` | 나감 |
  | **prod 배포** | `v1.*` 태그를 민다 | 태그 그대로 | `:latest` · `:<태그>` · `:<sha>` | 나감 |

  두 배포는 **같은 곳으로 나간다**(환경은 하나다). 앞자리는 **어떤 성격의 배포였는지**를 남긴다 — `0.` 은 시험 삼아 올린 것, `1.` 은 정식으로 내보낸 것. 화면에 뜬 번호만 보고 "지금 돌고 있는 게 실험인지 정식인지"를 안다.

  - dev 번호는 **빌드 번호(main 커밋 수)** 를 그대로 쓴다 — 지금까지 세던 번호가 끊기지 않는다.
  - prod 번호는 **사람이 정한다**(`v1.0.1`, `v1.1.0` …).
  - 빌드 번호는 스쿼시 머지마다 1씩 늘어 **큰 쪽이 무조건 최신**이다. PR 번호를 버전으로 쓰다가 **#159 다음에 #158이 배포된 적이 있다**(머지 순서와 PR 번호 순서는 다르다). PR 번호는 '어느 작업인지'로만 따로 들고 간다.
  - **`:latest` 를 움직이는 것이 곧 배포**다. main 머지는 그걸 건드리지 않는다.

### 1.4 설계 가치(우선순위)

1. **찾을 수 있어야 한다** — 이름을 정확히 몰라도, 어느 공간인지 몰라도 찾아진다.
2. **되돌릴 수 있어야 한다** — 삭제는 휴지통으로, 공간 간 전송은 복사로. 파괴적 동작만 확인창.
3. **한 화면에서 끝나야 한다** — 목록→열기→편집→저장→공유가 페이지 이동 없이 이어진다.

## 2. 아키텍처

### 2.1 스택

| 층 | 기술 |
|---|---|
| 프런트 | React 18, TypeScript, Vite 5, react-router 6 |
| 에디터 | CodeMirror 6 (`@uiw/react-codemirror`, `@codemirror/lang-markdown`, `language-data`) |
| 렌더링 | `react-markdown` + `remark-gfm`, `rehype-highlight` + highlight.js, `mermaid` 11 |
| 백엔드 | FastAPI, SQLAlchemy 2.x, Alembic, pydantic-settings |
| DB | SQLite (WAL, `foreign_keys=ON`, `busy_timeout=5000`, `NullPool`) |
| 스토리지 | 로컬 파일 또는 Cloudflare R2(boto3 S3v4) |
| 변환기 | LibreOffice(오피스·HWP→PDF), ffmpeg/ffprobe(영상 오디오 트랜스코딩) |
| 프록시 | Caddy (컨테이너 앞단, 업로드 바디 1GB) |
| 테스트 | pytest(백엔드), Playwright(E2E), Vitest(프런트 단위) |

### 2.2 런타임 구성

```
[브라우저] ──https──> [Cloudflare] ──> [Caddy] ──> [app 컨테이너]
                                                     ├── FastAPI (API + SPA 정적 서빙)
                                                     ├── SQLite  (/data/app.db)
                                                     └── 블롭 → 로컬(/data/blobs) 또는 R2
```

- Cloudflare가 TLS를 종료하므로 Caddy가 `X-Forwarded-Proto: https`를 강제한다. (안 하면 Secure 쿠키 로그인이 깨지고 공유 URL이 `http://`로 생성된다.)
- FastAPI는 `--proxy-headers`로 뜬다. OpenAPI 문서(`/docs`, `/redoc`)는 **비활성**.

### 2.3 데이터 모델

PK는 모두 uuid4 hex 32자 문자열(`new_id()`). 시각은 UTC.

| 엔티티 | 의미 | 핵심 컬럼 |
|---|---|---|
| **User** | 계정 | `email`(unique), `password_hash`(빈값=Google 전용), `role`(admin/member), `disabled_at`(soft-disable) |
| **Team** | 팀(이름 unique) | `name` |
| **TeamMember** | 팀 소속 | `(team_id, user_id)` unique |
| **Space** | **권한의 단위** | `type`(personal/team/org), `user_id`(personal), `team_id`(team) |
| **Node** | 폴더·파일 트리 | `space_id`, `parent_id`(self-FK, null=루트), `type`(folder/file), `name`(NFC), `size`, `mime`, `storage_key`, `sha256`, `created_by`, `updated_by`, `deleted_at`(휴지통) |
| **ShareLink** | 외부 공유 링크 | `token_hash`(sha256, 평문 미저장), `expires_at`, `password_hash`, `max_downloads`, `download_count`, `revoked_at` |
| **ApiToken** | 무인 업로드 자격 | `token_hash`(비밀부분 scrypt), 스코프 `space_id`/`node_id`, `expires_at`, `revoked_at` |
| **Favorite** | 즐겨찾기 | `(user_id, node_id)` unique |
| **NodeView** | 최근 열람 | `(user_id, node_id)` unique, `viewed_at` |
| **AuditLog** | 감사 로그(append-only) | `action`, `node_id`(**FK 아님** — purge 후에도 기록 유지), `detail`(500자 절단) |
| **EditLock** | 편집 잠금 | `node_id`가 **PK**(노드당 1개), `heartbeat_at`, TTL 30초 |

핵심 관계: `Node.creator` / `Node.editor` → `User` (`lazy="selectin"`, `viewonly=True` — N+1 방지, 읽기 전용).

### 2.6 버전은 서버가 말한다

화면 상단 뱃지는 **`/api/health`가 돌려주는 버전**을 표시한다. 이미지 빌드 때 `APP_VERSION`(= `v0.0.<PR#>`)을 런타임 스테이지의 ENV로 넣고, 서버가 그 값을 보고한다.

**왜 번들에 박지 않나**: 예전에는 vite가 플레이스홀더를 박고 빌드 뒤 `sed`로 치환했다. 그런데 프런트 소스가 안 바뀐 배포(백엔드만 변경)에서는 **번들 파일명이 그대로인데 내용만 달라진다.** vite의 파일명 해시는 치환 전 내용으로 계산되므로, CDN·브라우저는 같은 이름의 옛 바이트를 계속 내주고 **뱃지가 옛 버전을 표시한다.** 실제로 v0.0.147 배포 후 38분 동안 화면이 146으로 보였다(`cf-cache-status: HIT`).

서버가 말하면 캐시와 무관하게 항상 맞고, 덤으로 무거운 프런트 빌드 레이어가 버전과 무관해져 캐시가 그대로 재사용된다(배포 속도).

## 3. 기능 명세

### 3.1 인증 · 권한

- **로컬 로그인** — 이메일+비밀번호(scrypt). 비활성 계정·비밀번호 없는 계정(Google 전용)은 거부. 실패 메시지는 **하나로 통일**(계정 존재 여부 노출 금지).
- **레이트 리밋** — 이메일당 60초 10회 초과 시 429. 로그인에만 적용(프로세스 로컬).
- **Google OAuth(OIDC)** — `allowed_google_domain`이 **설정돼 있고** 이메일 도메인이 일치해야 한다(`hd` 클레임도 검사). 처음 보는 이메일은 자동 생성되며 **최초 1인은 admin**, 이후는 member.
- **세션** — 쿠키 세션(`SameSite=Lax`, prod에서만 `Secure`). 사용자가 삭제·비활성이면 세션을 비우고 401.
- **역할** — `admin` / `member` 둘뿐. 관리자도 **남의 개인 공간은 못 본다**(의도된 프라이버시 규칙).
- **"접근 가능 = 쓰기 가능"** — 읽기 전용 역할은 없다. 공간에 접근할 수 있으면 그 안에서 업로드·이동·삭제가 가능하다.

### 3.2 공간(Space)

| 타입 | 생성 시점 | 보이는 사람 | 표시 이름 |
|---|---|---|---|
| personal | 사용자 생성 시 자동 | 본인만(관리자도 제외) | 내 공간 |
| team | 관리자가 팀 생성 시 자동 | 그 팀 멤버 | 팀 이름 |
| org | 앱 최초 기동 시 1개 | 로그인한 모든 사람 | 전체 공간 |

`GET /api/spaces`는 **개인 → 소속 팀(이름순) → 전체** 순서로 준다.

### 3.3 파일 · 폴더

- 트리 구조(`parent_id`), 이름은 **NFC 정규화**, 같은 폴더 내 중복 시 `이름 (2)`로 자동 회피.
- **업로드** — 다중 파일, 폴더 업로드(`rel_path`로 폴더 자동 생성), 드래그앤드롭, 아카이브 서버 해제(`?extract=tar|zip`).
- **다운로드** — 파일 단건, 폴더는 tar.gz 스트리밍. 응답에 `X-Checksum-SHA256`.
  - **고른 여러 개**는 `GET /api/nodes/bundle?id=…&id=…` 로 tar.gz 하나에 담아 준다. 같은 공간에서
    골랐으면 그 **공간 표시 이름**(`space_display_name` — 사이드바와 같은 규칙)으로 된 디렉토리
    하나에 묶는다. 한 번에 `BUNDLE_MAX`(200)개까지.
  - 두 경로 모두 **목록을 먼저 `list()` 로 펼친 뒤** 스트리밍한다. 제너레이터째 넘기면 본문을
    흘려보낼 때가 되어서야 DB를 읽는데, 그때는 요청의 세션이 이미 닫혀 있다.
- **이동/복사** — 같은 공간=이동, **다른 공간=복사**(4장·D1 참조). 자기 하위 폴더로 이동 금지.
  - **제자리 이동은 아무것도 바꾸지 않는다.** 빈 이름 찾기(`unique_name`)는 `exclude_id`로
    **당사자를 빼고** 세고, 화면은 이미 그 폴더에 있는 항목을 아예 보내지 않는다(D16).
- **다중선택** — 트리에서 `Ctrl/⌘+클릭`으로 하나씩, `Shift+클릭`으로 범위. 고른 것들은 한꺼번에
  삭제·이동·복사·내려받기 할 수 있다(하단 바 또는 우클릭). 자세한 규칙은 4.6.
- **이름 변경** — 트리에서 제자리 편집. 열려 있는 탭·주소창 경로도 함께 갱신된다.

### 3.4 뷰어 · 에디터

- **탭** — 여러 파일을 탭으로 연다. 모든 탭이 마운트된 채 비활성은 숨겨져 **미저장·스크롤·편집잠금 상태가 보존**된다. 탭 줄은 좌우 드래그/휠 스크롤.
- **텍스트·마크다운** — CodeMirror 편집 + 라이브 프리뷰(양방향 스크롤 동기화). 코드 파일은 프리뷰 없이 풀폭.
- **자동 저장 / 수동 저장** — 토글 + `⌘S`. 저장은 `base_updated_at` 낙관적 잠금(충돌 시 409).
- **편집 잠금** — 노드당 1명. 30초 TTL 하트비트, 만료되면 다른 사람이 인수. 잠긴 파일은 읽기 전용 배너.
- **미리보기** — 이미지·영상(비호환 오디오는 AAC 트랜스코딩)·PDF·오피스/HWP(→PDF 변환, 캐시)·HTML(샌드박스 iframe).

### 3.5 검색

- 대상: **파일 이름 + 폴더 이름 + 텍스트 파일 내용**.
- 범위: **접근 가능한 모든 공간**을 동시에 검색해 합친다(결과에 공간명·경로 표시).
- 입력: `내 공간/폴더/파일명`처럼 **경로형으로 쳐도** 마지막 조각으로 찾는다. 사내 링크(해시)를 붙여넣으면 그 파일로 해석한다.
- 결과: 파일과 **폴더** 모두. 폴더를 고르면 그 폴더로 이동한다.
- UI: 상단 **주소창(오미니박스)** 이 검색창을 겸한다(4.2 참조).

### 3.6 공유

| 종류 | 대상 | 방법 |
|---|---|---|
| 사내 링크 | 로그인 사용자 | 주소창 📋 → `/files/<id>` 복사 |
| 외부 공유 링크 | 비로그인 | 공유 팝오버에서 발급 → `/s/<token>` |

외부 링크 옵션: **만료일**(기본/최대 설정값으로 상한), **비밀번호**(선택), **다운로드 횟수 제한**(선택), 언제든 **회수**.
터미널용 **원커맨드**(`curl … | sh`)를 함께 제공한다(폴더는 tar 해제까지).

발급된 링크 목록은 **누가·언제 발급했는지**(닉네임 + 발급일)를 먼저 보여준다 — 공용 공간에서는 "이 공개 링크 누가 만든 거지"가 회수 판단의 근거가 된다.

**공유 페이지(`/s/<token>`)만의 규칙**

- 헤더(파일명·테마 전환·다운로드)는 **스크롤해도 고정**된다.
- 마크다운 문서면 좌측에 **목차**(`#`/`##`/`###`)를 세우고, 누르면 그 문단으로 스크롤한다. 앱 내부 뷰어에는 넣지 않는다(이미 트리·탭·주소창이 있어 화면을 더 쪼갤 이유가 없다).
- 제목 id는 **줄 번호**(`h<줄>`)다. 제목 글자로 slug를 만들면 중복 제목·인라인 서식에서 목차와 본문이 어긋나므로, 렌더러(`MarkdownPreview`)와 추출기(`lib/toc.ts`)가 같은 규칙을 공유한다.

### 3.7 휴지통

- 삭제는 **soft delete**(확인창 없이 — 복원 가능하므로). 완전삭제만 확인창.
- 보존기간 경과 시 **자동 완전삭제**(기동 시 1회 + 6시간마다). 목록에 "삭제 예정까지 남은 시간" 표시.
- **복원은 원래 위치로.** 휴지통 항목을 사이드바 공간으로 **끌어다 놓아도 복원**된다(어느 공간에 놓든 원위치).

- **완전삭제는 DB를 먼저 확정하고, 본체는 그다음에 지운다.** 순서를 뒤집으면 중간에 실패했을 때
  휴지통엔 그대로 보이는데 알맹이만 사라진다(복원해도 빈 파일). 지금 순서의 최악은 '참조 없는
  오브젝트'인데 그건 `r2_orphans.py` 로 치울 수 있다 — **보이지 않는 손실보다 치울 수 있는 쓰레기가 낫다.**
  점검: `backend/scripts/missing_blobs.py`(읽기 전용) 가 '기록은 있는데 본체가 없는 파일'을 찾는다.

### 3.8 즐겨찾기 · 최근

- 트리 행의 ★로 즐겨찾기 토글, 즐겨찾기 전용 뷰 제공.
- 파일을 열면 "최근 열람"으로 기록(최대 40개 조회).

### 3.9 서버 전송 — 헤드리스 업로드·다운로드 (API 토큰)

브라우저 없이 서버·CI에서 파일을 **올리고 내린다**. UI의 `↕ 서버` 버튼 → **10분짜리 임시 토큰**을 발급하면 curl 명령에 자동으로 채워진다.

| 방향 | 엔드포인트 | 비고 |
|---|---|---|
| 올리기(파일) | `POST /api/upload` | 목적지는 토큰 스코프가 정함 |
| 올리기(폴더) | `POST /api/upload?extract=tar` | tar로 보내면 서버가 풀어 구조 재현 |
| 내리기(파일) | `GET /api/files/{id}` | `-fLOJ` |
| 내리기(폴더) | `GET /api/nodes/{id}/tar` | `\| tar xzf -` |

- **스코프**: 폴더 / 공간 / 없음(=발급자 개인 공간). **업로드와 다운로드에 같은 범위**가 강제되고 밖은 403.
- 토큰은 **삭제·공유·관리에는 쓸 수 없다**(전송 전용).
- 평문은 **발급 시 한 번만** 표시되고 서버엔 해시만 남는다. 다운로드도 감사 로그에 토큰 라벨이 남는다.
- 왜 읽기까지 여는지, 그 대신 무엇을 지키는지는 **D12** 참고.

**네 방향이 모두 대칭이다**: 로컬↔filesharer는 버튼·드래그, 원격지↔filesharer는 이 토큰 방식.

**팝오버 배치**: `⬆ 업로드`와 `⬇ 다운로드`를 **가로선으로 가른 별개 묶음**으로 둔다. 방향이 반대인 작업이 한 줄로 이어져 있으면 어디까지가 올리기인지 구분이 안 된다. 업로드 묶음 안에서는 **바로 붙여넣을 명령(파일 → 폴더)이 먼저**, 엔드포인트 URL은 *직접 스크립트를 짤 때* 쓰라는 라벨과 함께 맨 아래. 엔드포인트가 맨 위에 있을 때 "이 주소만 넣으면 되는 줄" 오해를 샀다 — **복사해서 바로 쓸 수 있는 것이 위**라는 규칙.

다운로드 줄은 **지금 대상이 무엇이냐**에 따라 파일용/폴더용으로 바뀐다(실재하는 id가 필요해 업로드처럼 두 줄을 항상 띄울 수 없다). 그래서 **지금 안 보이는 쪽이 존재한다는 안내를 한 줄 붙인다** — 파일을 보고 있으면 "폴더를 고르면 폴더째로 바뀐다", 폴더면 그 반대. 이 안내가 없었을 때 실제로 "폴더 다운로드는 없는 거 아니냐"는 질문을 받았다.

### 3.10 관리자

- **사용자**: 초대·생성, 역할 변경, 비활성화(자기 자신은 강등·비활성 불가).
- **팀**: 생성(팀 공간 자동 생성), 멤버 추가/제거, 삭제(활성 파일이 있으면 409 → `force=true`로 강제).
- **시스템**: 디스크 사용량·경고, 감사 로그 조회, 휴지통 관리(관리자 완전삭제).

### 3.11 에러 추적 (Sentry)

`SENTRY_DSN` 이 있으면 켜지고, 비면 **아무 일도 하지 않는다**(로컬·CI 기본값). 우리 서버에는 아무것도 띄우지 않는다 — sentry.io 로 보내기만 한다.

- **DSN은 둘이다. 절대 같은 것을 쓰지 않는다.**

  | | 어디서 쓰나 | 밖으로 나가나 |
  |---|---|---|
  | `SENTRY_DSN` | 서버 | **안 나간다** — `/api/health` 에도 싣지 않는다 |
  | `SENTRY_DSN_FRONTEND` | 브라우저 | `/api/health` 로 내려간다(원래 공개값) |

  `/api/health` 에는 **인증이 없다.** 서버 DSN을 거기 실으면 `curl` 한 번으로 누구나 가져가고,
  가져간 사람은 그 프로젝트에 가짜 이벤트를 밀어넣어 무료 한도(월 5천)를 태울 수 있다.
  그때부터 **진짜 에러가 버려진다** — 에러 추적을 붙인 이유가 그대로 사라진다.
  두 값은 sentry.io 에서 **서로 다른 프로젝트**로 만든다.
- **프런트 DSN은 서버가 `/api/health` 로 알려준다.** 번들에 박으면 환경마다 재빌드해야 하고, 파일명이 그대로인 배포에서 CDN이 옛 값을 내줄 수 있다(2.6과 같은 이유). SDK는 **DSN이 있을 때만** 동적으로 내려받아, 꺼져 있으면 번들이 커지지 않는다.
- `release` 는 **백엔드·프런트가 같은 형식**(`v1.0.0+153`)을 쓴다. 한 사건의 앞뒤(서버 예외 ↔ 화면 오류)가 이어져야 하기 때문.
- 개인정보는 보내지 않는다(`send_default_pii=False`). 누구인지는 **사용자 id** 로만 남긴다.

**보내기 전에 지우는 것** — 이건 편의가 아니라 **보안 장치**다. 에러 리포트는 제3자에 남고, 그 안에 '그대로 쓸 수 있는 열쇠'가 있으면 리포트를 본 사람이 파일을 받을 수 있다.

| 지우는 것 | 왜 |
|---|---|
| `/s/<token>` | **공유 토큰이 곧 파일 접근 권한** |
| `fsk_…` | API 토큰(업로드·다운로드 자격) |
| `X-Share-Password`·`Authorization`·`Cookie` | 자격증명 헤더 |

영리한 선별 대신 **이벤트를 통째로 훑는다** — URL·브레드크럼·예외 메시지·추가필드 등 경로가 많아 한 군데만 놓쳐도 새기 때문. 백엔드(`observability.py`)와 프런트(`lib/sentry.ts`)가 **같은 규칙**을 쓰고, 양쪽 테스트가 그걸 고정한다.

### 3.12 주기 백업

앱이 스스로 **주 1회·월 1회** 백업을 쌓는다. 별도 크론·서버 접속이 필요 없다.

```
backup/weekly/2026-W39/spaces/개인-joji.tar.gz
backup/weekly/2026-W39/spaces/크로스.tar.gz
backup/weekly/2026-W39/app.db.gz
backup/weekly/2026-W39/manifest.json
backup/monthly/2026-09/…
```

| 항목 | 규칙 |
|---|---|
| 대상 | **모든 공간**(개인·팀·전체). 개인 공간은 `개인-<닉네임>`으로 구분 |
| 내용 | 공간별 `tar.gz` + **DB 스냅샷**(`VACUUM INTO` → gzip) + `manifest.json` |
| 위치 | 운영 프리픽스와 **분리된** `backup/` (기본값, `BACKUP_PREFIX`) |
| 보관 | 주간 8회차(약 2개월) · 월간 12회차(1년). 초과분 자동 삭제 |
| 실행 | `APP_ENV=prod`에서만. 1시간마다 "이번 회차 키가 있는지" 확인 |

- **tar와 DB를 둘 다** 받는다. tar는 풀면 바로 파일이 나오고(이름·구조 보존), DB는 블롭 키(불투명 uuid)를 파일로 해석할 수 있게 해준다. 사용자·팀·공유링크·즐겨찾기는 DB에만 있다.
- **회차 판단은 시각이 아니라 키 존재 여부**다. `manifest.json`을 **맨 마지막에** 쓰므로, 도중에 죽으면 다음 틱이 그 회차를 다시 만든다. 배포마다 컨테이너가 재시작해도 중복 실행되지 않고 놓치지도 않는다.
- **복원은 앱이 하지 않는다.** 사람이 받아서 푼다(잘못된 자동 복원이 운영 데이터를 덮어쓰는 게 더 큰 사고).
- 점검: `backend/scripts/backup_list.py`(읽기 전용) · 수동 생성: `backend/scripts/backup_now.py --kind weekly [--force]`
- **복원**: `backend/scripts/restore_backup.py --kind weekly --stamp 2026-W40 --into <빈 폴더>` — 절차와 한계는 [`deploy/RESTORE.md`](../deploy/RESTORE.md).
- 화면 상단에 **마지막 백업 시각 배지**(`⛁ 2분 전`). 8일이 넘으면 주황색 — 주기보다 오래됐다는 신호. **로그인한 사람 모두**가 본다("내 파일이 언제 백업됐나"는 관리자만의 관심사가 아니다). 다만 규모(공간·파일 수·용량)는 자기가 못 보는 공간의 크기까지 드러내므로 **관리자에게만**. 조회에 실패해도 사라지지 않고 `⛁ 확인 불가`로 남는다 — 상태를 보려고 만든 것이 말없이 없어지면 제 기능을 못 한다.

**복원 리허설(2026-09-28, `weekly/2026-W40`)**: 실제 운영 백업으로 끝까지 해봤다. manifest sha256 5/5 일치, 블롭 27개 배치(양방향 불일치 0), 파일 27개·118 MB가 DB 기록 해시와 **27/27 일치**, 복원 폴더로 앱 기동 후 42 MB 파일을 HTTP로 받아 해시까지 일치. 결과는 RESTORE.md 에 기록.

## 4. UI/UX 규칙

### 4.1 화면 골격

```
┌ 상단 바 ─────────────────────────────────────────────────────────┐
│ 로고+버전 │ 주소창(경로/검색) 📋 │ 파일액션 │ 이메일 관리 테마 로그아웃 │
├──────────┬──────────────────────────────────────────────────────┤
│ 사이드바  │ 탭 줄: [탭][탭]…  │ 저장됨 자동저장 저장 삭제 닫기        │
│ (공간·트리)│──────────────────────────────────────────────────────│
│          │ 뷰어 / 에디터 / 목록                                  │
│ 휴지통    │                                                      │
└──────────┴──────────────────────────────────────────────────────┘
```

- **로고 폭 = 사이드바 폭**으로 맞춰 주소창 왼쪽 끝이 탭 줄 시작선과 정렬된다.
- 상단 바 우측 컨트롤(이메일·관리·테마·로그아웃)은 **항상 보여야 한다**. 파일 액션은 좁은 화면에서 가로로 접히되 우측 컨트롤을 밀어내지 않는다.
- 파일 액션은 **파일을 열든 안 열든 같은 자리**에 있다(열었으면 그 파일 대상, 아니면 현재 폴더 대상).

### 4.2 주소창(오미니박스)

| 상태 | 표시 | 동작 |
|---|---|---|
| 파일 열림·비입력 | `📄 공간/폴더/파일명` + 📋 | 📋 = 사내 링크 복사 |
| 클릭(포커스) | 경로 **전체 선택 유지** | 타이핑하면 경로를 통째로 대체 |
| 타이핑 중 | `🔎 검색어` + 결과 드롭다운 | 이름·내용·경로형 검색 |
| 결과 선택 / Esc / 바깥 클릭 | 다시 경로 표시 | 입력하던 검색어는 버린다 |

드롭다운은 **타이핑 중에만** 뜬다. 키보드: ↑↓ 이동, Enter 열기, Esc 취소.

### 4.3 드래그앤드롭 — 한 문장 원칙

> **같은 공간이면 이동, 다른 공간이면 복사. 판단은 "드래그한 항목의 공간"으로 한다.**

| 놓는 곳 | 결과 |
|---|---|
| 같은 공간의 폴더/헤더 | 이동 |
| 다른 공간의 폴더/헤더 | 복사(원본 유지) |
| 휴지통 | 휴지통으로 이동(확인창 없음) |
| 휴지통 항목 → 공간 | **원위치로 복원** |
| 로컬 파일/폴더 → 폴더·공간 | 그 위치로 업로드 |
| **고른 것 중 하나**를 끌면 | 고른 것 **전부**가 함께 간다(`application/x-node-ids`) |

### 4.4 테마 · 색 토큰

- 라이트/다크 두 테마. 색은 **전역 토큰**(`--primary`, `--ink`, `--canvas`, `--hairline` …)으로만 쓴다.
- 에디터 전용 토큰(`--ed-*`)은 **에디터 스코프 안에서만** 유효하다. **portal 등으로 그 밖에 렌더되는 요소는 반드시 전역 토큰을 쓴다.** (D4의 색 버그 원인)
- 상태색: 기본=차분한 회색, **활성/변경/강조=`--primary`(골드)**. 토글은 꺼짐=회색 트랙 / 켜짐=골드 트랙으로 **대비가 분명해야** 한다.

### 4.5 상태 표시

- 트리의 **현재 폴더·선택 파일**은 활성 하이라이트로 분명히 구분한다(브레드크럼이 없으므로 위치 표시의 주 수단).
- 미저장 변경은 탭의 ● 뱃지 + 상태 텍스트 색으로 **이중 표시**.
- 되돌릴 수 있는 동작은 확인창 없이, **되돌릴 수 없는 동작만** 확인창.

### 4.6 다중선택 — 트리 위에서

표를 없앤 뒤(레이아웃 개편) 선택의 무대는 **트리**다. 체크박스 열을 놓을 자리가 없으므로
탐색기·Finder와 같은 수식키 방식을 쓴다.

| 조작 | 결과 |
|---|---|
| `Ctrl/⌘ + 클릭` | 그 항목을 집거나 놓는다(토글). 기준점이 여기로 옮겨진다 |
| `Shift + 클릭` | 기준점부터 여기까지 **화면에 보이는 순서**로 범위 선택 |
| 그냥 클릭 | 선택을 풀고 **연다**(평범한 탐색이 우선이다) |
| `Esc` | 선택 해제 · `Delete`/`Backspace` | 고른 것 삭제 |

규칙:

- **범위는 '보이는 순서'다.** 접힌 폴더 안까지 집어가면 "화면에서 두 줄을 골랐는데 서른 개가
  지워지는" 일이 생긴다.
- **선택은 한 공간 안에서만 성립한다.** 공간마다 트리가 따로 있고, 섞어 고르면 "이동이냐
  복사냐"가 항목마다 갈린다. 다른 공간에서 고르기 시작하면 이전 선택은 버린다.
- **고른 표시(`.checked`)와 열린 표시(`.active`)는 달라야 한다.** 뜻이 다르기 때문이다 —
  전자는 행을 두르는 얇은 테두리, 후자는 왼쪽 굵은 막대. 한 행에 둘 다 붙을 수 있다.
- **다음 선택은 이전 값으로부터 계산한다.** 통째로 넘기면 연달아 빠르게 누를 때 리렌더 전의
  옛 선택을 덮어써 클릭 하나가 먹힌다(D15).

## 5. 테스트 전략

### 5.1 세 층위

| 층 | 도구 | 규모 | 책임 |
|---|---|---|---|
| 백엔드 | pytest | 171개 | API 계약, 권한, 스토리지, 공유·토큰, 마이그레이션 |
| 프런트 단위 | Vitest | — | 순수 로직(업로드 분할, 포맷 등) |
| 통합(E2E) | Playwright | 44개 / 20 spec | 실제 브라우저 사용자 흐름 |

E2E는 **빌드된 SPA를 백엔드가 서빙하는 상태**로 돌린다. 프런트를 고치면 재빌드→`backend/static` 복사, 백엔드를 고치면 재기동이 필요하다.

### 5.2 E2E 실행 규칙

- **`workers: 1` (직렬)** — 모든 테스트가 한 백엔드·한 계정·한 개인 공간을 공유한다. 전역 사이드바 트리 때문에 병렬로 돌리면 불안정해진다.
- 매 테스트 전에 `/api/test/reset`으로 데이터 초기화(그 라우트가 없으면 조용히 무시).
- 테스트 중 발생한 `pageerror`·`console.error`는 **테스트 실패로 간주**한다(허용 목록: favicon, CDN 챌린지, 네트워크 로드 실패).
- 테스트 데이터는 타임스탬프로 고유화한다.

### 5.3 회귀 테스트 원칙

1. **버그를 고치면 그 버그를 재현하는 테스트를 같이 넣는다.**
2. 새 테스트는 **"고장 상태에서 실패하는지"** 확인한 뒤에만 신뢰한다.
   (예: 크로스공간 복사 테스트는 코드를 강제로 '이동'으로 바꿔 **실패하는 것까지 확인**했다.)
3. **타이밍에 기대는 테스트는 테스트가 아니다.** "동시에 몇 개가 열려 있나" 같은 경합
   상태를 단언하면, 빠른 기계에선 열고 닫는 순서가 엇갈려 그냥 깨진다(실제로 CI에서
   태그 빌드가 한 번 깨졌다 — 코드는 멀쩡했다). **순수 함수·가짜 대역으로 로직만** 보게
   바꾼다. 못 바꾸겠으면 최소 50회 반복 실행으로 안정성을 확인하고 넣는다.
4. UI 요소를 **제거·개명하면 e2e를 먼저 grep**한다. 셀렉터가 사라지면 테스트 의도를 다시 표현한다.
   (예: 브레드크럼 제거 → 네비게이션 검증을 `.crumb` → `.tree-row.active`로 변경)
5. **내가 바꾼 코드가 아니라 사용자가 하는 동작을 테스트한다.** 내 diff만 겨누면 내가 안 건드린
   코드가 그 동작의 일부라는 걸 놓친다 — 다중선택 이동을 넣으면서 '전부 갔나'(위치)만 물었고,
   '그대로 갔나'(정체)는 안 물어 이름이 `(2)`로 바뀌는 걸 사용자가 먼저 찾았다(D16).
6. **드래그 테스트는 목적지를 '다른 곳'과 '같은 곳' 둘 다 시험한다.** 제자리로 놓는 것도
   사용자가 늘 하는 동작이고, 거기서만 드러나는 규칙이 있다(제자리 이동은 아무것도 바꾸지 않는다).
7. **트리에서 '안에 들어갔나'를 볼 땐 조상까지 걸리지 않게 겨눈다.** `li.tree-li` 를 'X를 품은
   것'으로 거르면 X의 **조상 li 까지** 걸려서, 옮겨지지 않은 항목도 통과한다. 대상 행 바로
   다음의 `ul`(그 폴더의 자식 목록)만 봐야 한다. 폴더가 접혀 있으면 그 `ul` 은 DOM에
   없으므로 먼저 들어가 펼친다. — ②를 안 지켰다가 실제로 헛도는 테스트를 하나 썼다.

### 5.3.1 드롭 매트릭스 — 빈칸을 세어 본다

드래그는 **무엇을 × 어디에** 의 격자다. 칸을 적어놓고 비어 있는 곳을 메운다.

| 놓는 곳 \ 실어나르는 것 | 단건 | 다중선택 | 로컬 파일 |
|---|---|---|---|
| 폴더 행 | files.spec | multiselect | upload.spec |
| **파일 행**(→ 부모 폴더) | — | multiselect(제자리) | upload.spec |
| 공간 헤더 | cross-space | multiselect | upload.spec |
| 휴지통 | trash.spec | multiselect | — |

- 2026-09-29 이 표를 처음 그렸을 때 **'파일 행 × 단건'과 '다중선택' 세 칸이 비어 있었고**,
  그 빈칸 하나에서 이름이 `(2)`로 바뀌는 버그가 살고 있었다(D16).
- '자기 하위 폴더로 이동 금지' 가드도 같은 날까지 테스트가 없었다. 깨지면 트리에 고리가
  생겨 하위 전체가 길을 잃는데, 아무도 지켜보지 않았다.

### 5.4 HTML5 드래그앤드롭 테스트 기법

네이티브 DnD는 합성 마우스 이벤트로 `dragstart`가 잘 발생하지 않는다. **DataTransfer 하나를 공유**해 직접 dispatch한다:

```js
const dt = new DataTransfer()
src.dispatchEvent(new DragEvent('dragstart', { dataTransfer: dt, bubbles: true }))
tgt.dispatchEvent(new DragEvent('dragover',  { dataTransfer: dt, bubbles: true, cancelable: true }))
tgt.dispatchEvent(new DragEvent('drop',      { dataTransfer: dt, bubbles: true, cancelable: true }))
```

앱의 dragstart 핸들러가 `dt`를 채우고 드롭 핸들러가 읽으므로 **실제 코드 경로**를 탄다. 크로스공간 복사·휴지통 복원 드래그가 이 방식으로 검증된다.

### 5.5 E2E가 못 잡는 것 — 시각 회귀

Playwright는 `overflow`로 **잘려 보이지 않는 요소도 클릭**하므로 테스트가 통과한다.

- 레이아웃·색 변경은 **브라우저에서 계산된 값을 직접 측정**해 확인한다(배경색이 on/off로 실제 달라지는지, 팝오버의 `offsetParent`가 overflow 밖인지, 뷰포트 안에 온전히 들어오는지).
- **"테스트 통과 = 사용자가 볼 수 있다"가 아니다.**

## 6. CI / CD

### 6.1 CI 잡 (`.github/workflows/ci.yml`)

트리거: PR(opened/synchronize/reopened) + `main` push.

| 잡 | 내용 |
|---|---|
| `secrets-scan` | gitleaks, **전체 히스토리**(`fetch-depth: 0`) |
| `backend` | Python 3.13, `ruff check .`, `pytest -q` |
| `frontend` | Node 22, `npm ci`, lint, vitest, build |
| `e2e` | `docker compose up -d --build` → 헬스 폴링 → Playwright(chromium). 실패 시 compose 로그·결과를 아티팩트로 업로드 |
| `deps-audit` | pip-audit + npm audit. **자문용**이라 다른 잡의 `needs`에 넣지 않는다 |
| `image` | `needs: [secrets-scan, backend, frontend]`. buildx 멀티아치, push일 때만 GHCR 푸시 |

### 6.2 이미지 빌드

- 태그: `ghcr.io/<owner>/filesharer:latest` + `:<sha>`.
- 플랫폼: push=`linux/amd64,linux/arm64`, PR=`linux/amd64`만(검증용).
- **함정**: 프런트 빌드를 arm64 에뮬레이션으로 돌리면 대형 의존성에서 멈춘다(6시간 타임아웃 경험). Dockerfile `web` 스테이지에 **`--platform=$BUILDPLATFORM`** 을 줘 네이티브로 한 번만 빌드하고 결과물만 복사한다.
- 버전: `VERSION` 파일(제품 버전) + 커밋 메시지 첫 줄의 **마지막 `#<n>`**(빌드 번호)을 빌드 인자로 넘긴다. 서버가 `/api/health`로 보고한다(2.6).
- **`needs`에 `e2e`가 들어 있다** — 이 잡이 곧 배포이기 때문이다(6.3).

### 6.3 배포(CD)

배포 잡은 **없다**. 서버의 watchtower가 GHCR `:latest`를 약 60초 폴링해 컨테이너를 교체한다.
따라서 **`:latest` 를 움직이는 것이 곧 배포**이고, 그건 **태그를 밀 때만** 일어난다.

```bash
# 평소 — 자유롭게 머지한다. 이미지는 :b<빌드> 로만 쌓이고 아무데도 안 나간다.
gh pr merge 161 --squash --delete-branch

# ① dev 로 내보내기 — 시험 삼아 올려본다. 번호는 지금 빌드 번호를 그대로.
git fetch origin main && git tag v0.0.$(git rev-list --count origin/main) && git push origin --tags

# ② prod 로 내보내기 — 정식. 번호는 사람이 정한다.
gh release create v1.0.1 --generate-notes
```

머지가 곧 배포이던 시절에는 PR마다 "그린 확인 → 머지 → 배포 확인"을 반복해야 했다.
갈라 놓으면 **자유롭게 머지하고 원할 때 한 번** 내보내면 된다. 롤백도 옛 태그를 다시 밀면 끝이다.
(원본 서버는 인바운드 SSH가 IP 제한이라 push형 배포를 쓰지 않는다.)

**그래서 `image` 잡이 곧 배포다.** 처음엔 SSH로 배포하는 `deploy` 잡이 따로 있었고 그게 `needs: [image, e2e]` 였다. watchtower로 바꾸면서 `deploy` 를 지웠는데, **그때 e2e 게이트도 같이 사라졌다.** 한동안 "e2e가 깨져도 배포는 나가는" 상태였다 — 구조를 바꿀 때 따라오지 않은 설정의 전형이다. 지금은 `image` 가 그 조건을 물려받았다.

**배포 확인 방법**: `curl -s https://<도메인>/api/health` → `version`(제품)과 `build`(머지 PR)를 본다. 제품 버전이 그대로인 배포는 `build` 로 판별한다. 번들 문자열을 긁는 옛 방법은 쓰지 않는다(2.6).

### 6.4 머지 규칙

- CI 전부 그린, 특히 **`backend`와 `e2e`를 명시적으로 확인**한 뒤 머지한다(확인과 머지를 한 명령으로 묶지 않는다).
- 스쿼시 머지 + 브랜치 삭제. 스쿼시 커밋 제목의 `(#NN)`이 곧 빌드 번호가 된다.
- **3개쯤 모아 연달아 머지한다.** 워크플로 `concurrency`(`cancel-in-progress: true`)가 **최신 실행만** 남기므로, 연속 머지는 **e2e도 배포도 마지막 한 번**만 돈다. 모아둘 필요는 없고 **연달아 머지하기만** 하면 된다.
  - 중간 상태는 어차피 배포되지 않는다. 검증해야 할 것은 **최종 합쳐진 상태**이고 마지막 실행이 그걸 본다.
  - 처음엔 "머지마다 기록을 남겨야 한다"며 main을 취소하지 않게 했는데, 그러면 실행이 **줄을 서서** 제일 느린 e2e(약 3분)를 머지 횟수만큼 반복했다. 그 기록은 각 PR의 CI에 이미 있다.
- 저장소가 public이라 Actions는 **무제한 무료**다. 줄이려는 것은 비용이 아니라 **배포 횟수와 확인 수고**다.

## 7. 운영 · 보안

### 7.1 설정

루트 `.env`(gitignored)를 cwd와 무관하게 읽는다. 주요 키: `APP_ENV`, `SECRET_KEY`, `BASE_URL`, `FRONTEND_URL`, `DATA_DIR`, `DATABASE_URL`, `STORAGE_BACKEND`, `R2_*`(+ **`R2_PREFIX`로 dev/prod 오브젝트 분리**), `MAX_UPLOAD_MB`, `SHARE_*`, `TRASH_RETENTION_DAYS`, `DISK_WARN_RATIO`, `ADMIN_*`, `GOOGLE_*`, `ALLOWED_GOOGLE_DOMAIN`.

### 7.2 한계값(기본)

| 항목 | 값 |
|---|---|
| 업로드 크기 | `MAX_UPLOAD_MB`(기본 1024MB), Caddy도 1GB로 별도 제한 |
| 아카이브 해제 | 최대 5000개 항목, 총 해제 용량 = 업로드 상한×50(zip bomb 방지) |
| 휴지통 보존 | 기본 7일, 기동 시 + 6시간마다 청소 |
| 내용 검색 | 파일당 512KB, 쿼리당 400개 스캔(※ FTS 인덱스 도입으로 대체 예정) |
| 공유 만료 | 기본 7일 / 최대 30일 |
| 토큰 만료 | 최대 365일 |
| 감사 로그 조회 | 1~500건 |

### 7.3 보안 규칙

- **비밀값은 전부 해시**: 비밀번호·공유 비밀번호·토큰 비밀부분은 scrypt, 공유 토큰은 sha256. 비교는 `compare_digest`.
- **평문은 한 번만**: 공유 토큰·API 토큰 평문은 발급 응답에만 있고 저장·로그에 남지 않는다.
- **타이밍 공격 차단**: 없는 토큰 id에도 더미 scrypt 검증을 수행한다.
- **경로 탈출 차단**: 이름은 NFC 정규화 + 경로 성분 제거, SPA 폴백은 `is_relative_to(STATIC_DIR)` 검사, 아카이브는 `..`·절대경로·심볼릭링크 거부.
- **HTML 미리보기**: `Content-Security-Policy: sandbox` + `nosniff` + iframe `sandbox`/`srcdoc`.
- **변환기 샌드박스**: LibreOffice·ffmpeg에는 6개 환경변수와 격리된 `HOME`만 전달(앱 시크릿 차단), `ulimit`으로 코어·CPU·파일크기 제한.
- **fail-fast**: prod인데 `SECRET_KEY`가 플레이스홀더면 기동 실패. `/api/test/reset`은 플래그가 켜지고 prod가 아닐 때만 **라우트 자체가 존재**한다.
- **CORS 미들웨어 없음** — 프런트가 동일 오리진이므로 필요 없다(dev는 Vite 프록시).

### 7.4 운영 체크리스트

- 백업: `filesharer-data` 볼륨 하나(= SQLite + 로컬 블롭). R2 사용 시 버킷은 별도.
- 마이그레이션: 기동 시 `alembic upgrade head`가 자동 실행된다(로컬·컨테이너·테스트 동일 경로).
- 프로덕션 점검: `make prod-check`.
- **프로덕션에서는 읽기 전용 확인만** 한다. 토큰·비밀번호를 프로덕션 화면에 입력하지 않는다.

## 8. 결정 기록 (Decision Log)

각 항목은 **결정 / 이유 / 함정·교훈**. 코드를 읽어도 알 수 없는 "왜"만 적는다.

### D1. 공간 간 전송은 '이동'이 아니라 '복사'

- **결정**: 다른 공간으로 드래그하면 원본을 남기고 복사한다. 같은 공간 안에서만 이동.
- **이유**: 공간은 소유·권한의 경계다. 개인 공간 파일을 전체 공간으로 "옮기면" 원래 위치에서 사라져 소유자가 자료를 잃는다. 복사는 되돌릴 필요가 없어 안전하다.
- **판단 기준**: **드래그한 항목의 실제 공간 vs 놓은 대상 공간**. ~~활성(보고 있는) 공간~~이 아니다.
- **함정**: 양쪽 공간 트리를 동시에 보여준 뒤, "활성 공간 기준" 판단이 크로스공간 드롭을 이동으로 오판했다. 대상이 마침 활성 공간이면 참이 되어 이동이 실행되고, 이름 충돌 시 `이름 (2)`로 리네임까지 됐다.
- **해결**: dragstart에서 `application/x-node-space`(소스 공간)를 payload에 실어 드롭 지점에서 판단. 공간 헤더·폴더·경로 드롭을 함수 하나로 통일.

### D2. 브레드크럼을 없애고 상단 '주소창'으로 통합

- **결정**: 브라우즈 모드의 경로 바를 제거. 상단 검색창이 **열린 파일의 경로를 보여주는 주소창**을 겸하고, 타이핑하면 검색 모드로 바뀐다.
- **이유**: ① 파일을 연 상태와 안 연 상태의 배치가 달라 일관성이 없었다. ② 경로와 검색이 같은 자리를 쓰면 크롬처럼 "현재 위치 = 검색 입력"이라는 **하나의 멘탈 모델**이 된다. ③ 세로 한 줄 절약.
- **함정**: 주소 모드에서 클릭하면 캐럿이 옮겨가 전체선택이 풀리고, 타이핑이 **경로 뒤에 붙어** 검색이 되지 않았다. `onMouseUp` 기본동작을 막아 전체선택을 유지했다.
- **부수 효과**: 네비게이션 검증을 크럼이 아니라 **트리의 현재 폴더 활성 표시**로 바꿔야 해서 e2e 3개를 수정했다.

### D3. 사내 링크 복사는 주소창 📋 하나로 일원화

- **결정**: 공유 팝오버의 '사내 링크 복사' 행을 제거하고 주소창 📋만 남긴다.
- **이유**: 같은 기능이 두 곳에 있으면 "어느 게 그 링크인지" 혼란이 생긴다. 팝오버는 **외부 공유**라는 다른 목적에 집중시킨다.
- **결과 역할 분담**: 주소창 📋 = 사내 링크 / 공유 팝오버 = 외부 공유 링크.

### D4. 파일 액션은 상단 바, 저장·삭제·닫기는 탭 줄

- **결정**: 다운로드·업로드·공유는 상단 바, 저장·자동저장·삭제·닫기는 탭 줄. 별도 에디터 툴바 줄은 없앤다.
- **이유**: "파일 자체에 대한 액션"과 "편집 세션에 대한 액션"의 분리. 탭이 많아져도 편집 컨트롤이 탭 옆이라 손이 가깝고 줄 하나를 절약한다.
- **구현**: 활성 탭의 에디터가 **React portal**로 탭 줄 슬롯에 저장 컨트롤을 렌더한다(상태는 에디터가 소유 → 탭별 dirty·자동저장이 섞이지 않는다).
- **함정(중요)**: portal로 DOM 트리 밖에 나간 요소가 **에디터 스코프 전용 CSS 변수**를 참조해, 그 위치엔 변수가 없어 배경이 투명·글자색이 상속으로 떨어졌다. 자동저장 토글이 켜도 꺼도 색이 변하지 않았다.
- **교훈**: **portal된 UI는 반드시 전역 토큰을 쓴다.** 스코프 변수는 그 스코프 안에서만.

### D5. 검색은 이름 + 내용, 모든 공간 동시, 경로형 입력 허용

- **결정**: 파일명뿐 아니라 텍스트 내용까지, 접근 가능한 **모든 공간**을 합쳐 검색한다. 경로형 입력도 마지막 조각으로 찾는다. 폴더도 결과에 뜨고 선택하면 이동한다.
- **이유**: 사용자는 "그 파일 어디 있더라"를 이름으로만 기억하지 않는다. 검색 전에 공간을 고르게 하면 검색의 의미가 없다.

### D6. 내용 검색은 FTS5 **trigram** 인덱스로

- **문제**: 검색 1회마다 텍스트 파일 블롭을 **스토리지에서 하나씩 읽어** 스캔했다. 원격(R2)이면 파일 수만큼 네트워크 왕복이 생기고, 프런트가 모든 공간을 동시에 검색하므로 공간 수만큼 배가된다.
- **결정**: 저장 시점에 내용을 SQLite **FTS5** 인덱스에 넣고, 검색은 인덱스만 조회한다(질의 중 원격 읽기 0).
- **왜 trigram인가**: 기본 토크나이저는 **한국어를 단어로 못 쪼갠다**(띄어쓰기 기준). `trigram`은 3글자 부분일치를 인덱스로 가속해 한국어 substring 검색에 맞다. 3글자 미만은 인덱스 가속을 못 받지만 결과는 정확하고 원격 읽기도 없다.
- **이름 검색은 그대로 `LIKE`**: name 컬럼은 짧고 행 수도 적어 이미 빠르며 2글자 한글도 문제없다. 병목은 내용 검색뿐이었다.

### D7. 휴지통은 soft delete + 자동 완전삭제, 복원은 '원위치'로

- **결정**: 삭제는 휴지통으로(복원 가능), 보존기간 후 자동 완전삭제. 복원은 **원래 있던 위치**로.
- **드래그 복원**: 휴지통 항목을 사이드바 공간으로 끌어다 놓으면 복원된다. **어느 공간에 놓든 원위치로** 간다 — 이 제스처는 "목적지를 고르는 것"이 아니라 "휴지통에서 꺼내는 것"이기 때문이다.

### D8. 배포는 pull형(watchtower), 버전은 PR 번호

- **결정**: CI가 이미지를 `:latest`로 올리면 서버의 watchtower가 폴링해 교체한다. 버전 뱃지는 스쿼시 커밋의 `(#NN)`에서 뽑아 `v0.0.NN`.
- **이유**: 서버에 배포 권한을 주지 않고도 자동 배포가 된다. 화면의 버전만 보면 **어떤 PR이 라이브인지** 즉시 알 수 있다.
- **함정**: 멀티아치에서 **arm64 프런트 빌드를 에뮬레이션으로 돌리면 멈춘다**(6시간 타임아웃까지 갔다). `--platform=$BUILDPLATFORM`으로 네이티브 1회 빌드.

### D9. HTML5 드래그앤드롭은 '합성 DataTransfer'로 테스트한다

- **문제**: 네이티브 DnD는 합성 마우스 이벤트로 `dragstart`가 잘 발생하지 않아 자동화가 어렵다.
- **결정**: `DataTransfer` 하나를 만들어 `dragstart → dragover → drop`을 직접 dispatch한다. 앱 핸들러가 그 객체를 채우고 읽으므로 실제 코드 경로를 탄다.
- **원칙**: 이런 테스트는 반드시 **"고장 상태에서 실패하는지"** 를 확인하고 나서 신뢰한다.

### D10. e2e가 못 잡는 '시각 회귀'는 브라우저에서 측정한다

- **사례**: 상단 바로 옮긴 팝오버가 `overflow` 때문에 잘려 보이지 않았는데 **Playwright는 클릭이 되어 테스트가 통과**했다. 실제 화면을 보고 발견했다.
- **원인**: `overflow-x: auto`를 주면 세로도 잘린다. 절대배치 팝오버의 컨테이닝 블록이 그 overflow 안이면 잘리고, 밖(뷰포트)이면 안 잘린다.
- **원칙**: 레이아웃·색 변경은 **e2e만 믿지 않는다**. 계산된 스타일과 위치를 직접 측정한다.

### D11. 관리자도 남의 개인 공간은 볼 수 없다

- **결정**: `admin` 역할은 사용자·팀·시스템을 관리하지만, **개인 공간의 내용에는 접근하지 못한다.**
- **이유**: 사내 도구라도 개인 공간은 사적 영역이다. 관리 권한과 열람 권한을 분리해 두면 "관리자가 다 본다"는 불신을 없앨 수 있다.

### D12. API 토큰은 '스코프 안에서' 올리고 내린다 (개정)

- **처음 결정**: 무인 토큰은 **업로드 전용**. 서버·CI에 두는 자격증명은 유출 위험이 높으니 피해 범위를 "쓰기 전용"으로 잘라 둔다.
- **왜 바꿨나**: 그러면 **filesharer → 원격지로 파일을 내릴 방법이 "공개 공유 링크"밖에 없었다.** 사내 서버에 파일 하나 내리자고 **인증 없는 공개 URL**(기본 7일)을 발급하는 셈이라, 오히려 그쪽이 더 위험했다.
- **개정 결정**: 읽기도 **같은 토큰·같은 스코프**로 연다(`enforce_read_scope`). 범위는 방향과 무관하게 강제되고, 범위 밖은 403.

  | | 공유 링크(기존 유일한 방법) | 토큰 다운로드(개정) |
  |---|---|---|
  | 인증 | 없음(공개 URL) | 헤더 Bearer |
  | 범위 | 그 파일 전체 공개 | 폴더/공간 스코프 |
  | 만료 | 기본 7일 | UI 기본 10분 |

  즉 **공개 URL을 스코프·단수명·헤더 인증으로 대체**하므로 실질 보안은 올라간다.
- **지킬 것**: UI는 계속 **10분 만료** 토큰을 발급한다. API로는 최대 365일까지 만들 수 있는데, 읽기가 열린 만큼 **장수명 토큰의 위험이 커졌다.** 다운로드도 감사 로그에 토큰 라벨을 남긴다.
- **UI**: 버튼은 방향을 합쳐 `↕ 서버`, 팝오버는 `서버 전송`(⬆ 업로드 / ⬇ 다운로드). 예전 이름이 `서버 업로드`여서 "다운로드는 없다"는 오해를 샀다.

### D14. 백업은 '운영과 다른 경로'에, 회차는 '시각'이 아니라 '키'로 판단한다

- **문제**: R2는 튼튼하지만 지켜주지 못하는 게 있다 — **우리 실수**다. 이번 주에도 정리 스크립트로 고아 객체 992개를 지웠다. 그리고 SQLite는 **서버 로컬 디스크**에 있어서, 그 VM이 죽으면 R2의 블롭은 이름도 구조도 모르는 uuid 덩어리가 된다.
- **결정**:
  1. 백업은 `backup/` — **운영 프리픽스와 분리**. 운영 키를 훑는 스크립트가 백업까지 지울 수 없어야 한다. `r2_orphans.py`는 prefix에 `backup`이 스치기만 해도 중단한다.
  2. **tar.gz + DB 스냅샷 둘 다.** 하나만으로는 반쪽이다.
  3. 회차 식별은 **키 존재 여부**(`weekly/2026-W39/manifest.json`). 크론도, 마지막 실행 시각 테이블도 필요 없다.
  4. `manifest.json`을 **맨 마지막에** 쓴다 → 중간에 죽은 회차는 미완성으로 남고 다음 틱이 다시 만든다.
  5. 자동 실행은 **prod에서만.** dev 머신이 같은 버킷을 보면 `backup/`을 건드려 운영 백업을 지울 수 있다.
- **안 한 것**: 앱에서의 **자동 복원**. 덮어쓰기 사고가 백업 없는 것보다 위험하다. 복원은 사람이 받아서 푼다.
- **안전장치를 테스트로 고정**: 회차 이름이 `2026-W39`/`2026-09` 형식이 아니면 삭제를 **거부**한다(`""`, `..`, `../prod` 등). 이 검사가 없으면 빈 회차 이름 하나로 백업 전체가 날아간다.
- **왕복 테스트로 고정**: 복원은 tar 의 '사람이 읽는 경로'와 DB 의 `storage_key` 를 맞춰 붙인다. 그래서 공간 이름 규칙(`backup_space_name`)이 바뀌면 복원이 **조용히** 깨진다. `test_backup_restore_roundtrip` 이 백업→복원→바이트 비교까지 돌려 이 짝을 묶어 둔다(규칙을 바꾸면 테스트가 깨진다 — 실제로 깨뜨려 확인했다).

### D19. '스트리밍'이라고 적어놨다고 스트리밍이 되는 건 아니다

- **사건**: 사용자가 "다운로드가 생각보다 오래 걸린다". 파일 첫 줄에는
  *"서버 임시파일·메모리 누적 없음"* 이라고 적혀 있었는데 **사실이 아니었다.**
- **원인**: 생성기가 `tar.addfile(info, body)` 로 **파일 하나를 통째로** 버퍼에 쌓고,
  그게 끝난 **뒤에야** `yield` 했다. 40MB 파일이면 40MB가 메모리에 앉아 있었고 그동안
  클라이언트는 한 바이트도 못 받았다. 업로드 한도가 500MB라 그만큼이 한 번에 뜰 수 있었다.
  거기에 파일마다 `exists()` 로 저장소에 한 번 더 물어봤다 — 원격에선 그게 왕복 한 번이다.
- **고친 방식**: 만드는 쪽을 스레드로 빼고 **유계 큐**로 잇는다. 큐가 차면 만드는 쪽이
  막힌다 — 그게 곧 메모리 상한이고, "받아가는 만큼만 만든다"는 뜻이다. 덤으로 저장소
  읽기와 클라이언트 전송이 겹친다. `exists()` 는 없앴다(열어보면 어차피 안다).

  | | 이전 | 이후 |
  |---|---|---|
  | R2 왕복 (파일 4개) | 8번 (HEAD+GET) | **4번** |
  | 첫 바이트 | 350ms | **123ms** |
  | 40MB 파일의 서버 메모리 | 40MB | **~640KB 고정** |

- **주의 셋**: ① ORM 객체를 스레드로 넘기지 않는다 — 세션은 스레드 안전하지 않다.
  넘기기 전에 `(key, 이름, 크기)` 평범한 튜플로 바꾼다. ② 클라이언트가 끊으면 만들던
  스레드를 풀어줘야 한다(안 그러면 `put` 에서 영영 막혀 쌓인다). ③ 본체를 못 열면
  **헤더를 쓰기 전에** 건너뛴다 — 쓰고 나서 실패하면 tar 가 통째로 깨진다.
- **테스트는 결과물이 아니라 흐름을 고정한다**(`test_tar_stream.py`): 다 읽기 전에 첫
  바이트가 나오는가, 파일당 저장소를 한 번만 부르는가, 받는 쪽이 멈추면 만드는 쪽도
  멈추는가, 끊으면 스레드가 접히는가. 옛 구현으로 되돌리면 5개가 실패한다.
- 압축 수준은 9 → 6. 이미 압축된 파일(pptx·png)에는 9가 CPU만 태우고 크기는 그대로였다
  (측정: 같은 크기, 1.3배 빠름). **범인이 아니었지만 공짜라 같이 낮췄다.**
- **다음 파일을 미리 연다 — 개수가 아니라 `PREFETCH_BYTES`(총 바이트)로.** 메모리를 잡고
  다시 재보니 남은 시간의 대부분이 '파일을 하나씩 차례로 여는 왕복'이었다.

  처음엔 개수(3개)로 잡았는데, **파일 크기에 따라 정반대였다**. 실측(실제 R2):

  | | 200KB × 20개 | 2MB × 6개 |
  |---|---|---|
  | 앞서 3개 | 2.35초 | 3.1초 |
  | 앞서 8개 | **1.23초** | 3.12초(느려짐) |

  큰 응답을 여럿 동시에 열면 **같은 회선을 나눠 써 지금 보내는 파일이 밀린다.**
  바이트로 재면(4MB 예산) 작은 파일은 많이, 큰 파일은 한둘만 앞선다 — 양쪽 다 이득이다.

  | 실제 R2 · 같은 블롭 | v0.0.165 | 개수 3개 | **바이트 예산** |
  |---|---|---|---|
  | 200KB × 20개 | 11.29초 | 2.35초 | **1.24초** (원래 대비 **9.1배**) |
  | 2MB × 6개 | 4.17초 | 3.1초 | **2.72초** |

- **읽기 버퍼(16KB)는 범인이 아니었다.** 1MB로 키워봤지만 이득이 없었다(0.91~1.00배).
  적어두는 이유는 다음 사람이 같은 데를 또 파지 않게 하기 위해서다.
- **잡음에 속지 않는다.** 회선 상태가 흔들려 같은 설정이 2.37~5.74초로 나왔다. 한 번 재고
  "느려졌다"고 판단할 뻔했다. **교차로 여러 번 재고 범위를 같이 본다** — 중앙값만 보면
  겹치는 분포를 차이로 착각한다.
- **측정 없이 짚지 않는다.** 처음엔 압축을 의심했는데 6.4MB에 0.1초로 범인이 아니었다.
  메모리를 고치고 다시 재서야 '여는 왕복'이 드러났다. 한 번 고치고 **다시 재는 것**이
  절반이다.

### D18. 되돌릴 수 없는 일은 트랜잭션이 확정된 **뒤에** 한다

- **사건**: D17을 고치고 나서 보니, 실패하던 동안 **파일 본체는 이미 지워지고 있었다.**
  `purge_subtree` 가 `storage.delete()` 를 먼저 부르고 그다음 DB 행을 지웠는데, 뒤이은
  `flush()` 가 FK로 터지면 DB만 롤백된다. 결과는 **휴지통에 그대로 보이는데 알맹이가 없는 항목**
  — 복원하면 빈 파일이다. 사용자는 영문을 모른다.
- **원칙**: DB 트랜잭션 안에서 **트랜잭션 밖의 되돌릴 수 없는 일**(오브젝트 삭제, 메일 발송,
  결제)을 하지 않는다. 커밋이 끝난 뒤에 한다.
- **어느 쪽으로 틀릴지 고른다.** 두 순서 모두 실패할 수 있고, 남는 잔해가 다르다.

  | 순서 | 실패하면 남는 것 | 치울 수 있나 |
  |---|---|---|
  | blob 먼저 | **기록은 있는데 본체가 없다** | 못 한다 — 파일은 이미 사라졌다 |
  | DB 먼저 | 참조 없는 오브젝트 | `r2_orphans.py` 로 치운다 |

  **보이지 않는 손실보다 치울 수 있는 쓰레기가 낫다.**
- `delete_blobs` 는 하나가 실패해도 멈추지 않는다. 멈추면 이미 DB에서 사라진 나머지의 본체가
  전부 남는다.
- 점검 수단을 같이 둔다: `scripts/r2_orphans.py`(참조 없는 오브젝트) ↔
  `scripts/missing_blobs.py`(본체 없는 기록). 서로 반대 방향이고, **후자가 더 나쁘다**
  — 전자는 공간만 축내지만 후자는 사용자가 열면 실패한다.

### D17. 지우기 전에 '그것을 가리키는 것'을 먼저 치운다

- **사건**: Sentry를 켜자마자 프로드 로그에 `FOREIGN KEY constraint failed` 가 쌓여 있었다.
  **휴지통 자동삭제가 계속 실패하고 있었고**, 아무도 몰랐다.
- **원인**: `purge_subtree` 가 blob·검색인덱스·`ShareLink` 만 치우고 노드를 지웠다. 그런데
  `nodes.id` 를 참조하는 FK는 다섯이다 — `share_links`·`favorites`·`node_views`·`edit_locks`·
  `api_tokens`. `PRAGMA foreign_keys=ON`(db.py) 이라 하나만 남아도 삭제 전체가 엎어진다.
- **왜 오래 숨었나**: 테스트가 전부 **'올리고 바로 지운' 파일**만 다뤘다. 참조가 하나도 없으니
  통과한다. 사람은 파일을 **열어보고**(`node_views`), 별표를 달고(`favorites`), 편집하다가
  (`edit_locks`) 지운다. 자동삭제는 30일 지난 파일이 대상이라 **거의 전부** 열어본 적이 있다.
- 자동 스위퍼만이 아니라 **휴지통의 '완전 삭제' 버튼도 같이 고장나 있었다.**
- **규칙**: 행을 지우는 코드를 쓸 땐 그 테이블을 가리키는 FK를 **전부 세어보고** 시작한다.
  `audit_log.node_id` 는 일부러 FK가 아니다 — 기록은 대상이 사라져도 남아야 한다.
- §5.3 ④("내 diff가 아니라 사용자의 동작을 테스트한다")의 세 번째 사례다.

### D16. 빈 이름 찾기는 '당사자'를 빼고 센다

- **사건**: "여러 개를 선택해서 이동시키면 이름이 변경되는데, 파일에 대한 동일성을 확인하지
  않는 것 같다." 맞는 지적이었다.
- **원인**: `unique_name(space, parent, name)` 이 같은 자리의 같은 이름을 찾을 때 **옮기는
  당사자까지** 셌다. 제자리로 옮기면 자기 이름과 부딪혀 `이름 (2)` 가 된다.
- **왜 다중선택에서 터졌나**: 트리에서 **파일** 위에 놓으면 대상은 '그 파일의 부모 폴더'다.
  여러 개를 골라 형제 위에 놓는 건 전부 제자리 이동이라 **고른 것 전부**가 리네임됐다.
  단건 드래그로는 잘 안 만나는 조합이라 그동안 드러나지 않았다.
- **고친 방식**: 두 겹으로 막는다.
  - 서버 — `unique_name(..., exclude_id=node.id)`. 이동·이름변경·복원이 이걸 쓴다.
    **새로 만드는 쪽(업로드·폴더 생성·복사)은 당사자가 없으므로 그대로 둔다** — 복사는
    원본과 부딪혀야 맞다.
  - 화면 — 같은 공간 안에서 이미 그 폴더에 있는 항목은 애초에 보내지 않는다. 보내봐야
    달라지는 것 없이 `updated_at`·`updated_by` 만 갱신된다.
- **규칙**: "이름이 겹치는가"를 물을 땐 **누구와 겹치는가**를 같이 물어야 한다. 자기 자신은
  남이 아니다.

### D15. 기능을 지울 땐 그 기능의 테스트도 같이 사라진다는 걸 셈에 넣는다

- **사건**: "다중 선택이 없어진 것 같은데." 사용자가 말할 때까지 아무도 몰랐다.
- **경위**: 다중선택은 **메인 표** 위에 체크박스로 있었다(#60). 트리 전용 레이아웃 개편(#96)이
  그 표를 없애면서 다중선택도 같이 내렸고("다중선택 대량작업은 트리 전용 전환으로 비활성"),
  후속 정리(#97)가 도달 불가가 된 코드와 함께 `multiselect.spec.ts` 까지 지웠다.
- **왜 아무도 몰랐나**: 지운 것이 **기능과 그 기능의 감시자 둘 다**였다. 남은 테스트는 전부
  초록이었다 — 없어진 기능을 보는 눈이 하나도 없었으니까.
- **규칙**: UI를 걷어낼 때 같이 지우는 테스트가 있다면, 그건 *구현*을 잃는 게 아니라 *약속*을
  잃는 것이다. 약속을 접는 것이면 그렇게 적고, 접는 게 아니면 **새 UI 기준으로 다시 쓴다.**
- 되살릴 때 드러난 것: 드래그 프로토콜(`application/x-node-ids`)은 양쪽에 그대로 살아 있었다.
  배관은 남고 손잡이만 사라진 상태로 6개월 가까이 돌았다.

### D13. 렌더러 매핑(`components`)은 JSX 안에 인라인으로 두지 않는다

- **증상**: 에디터에서 문서를 보고 있으면 **가만히 있어도 10초쯤마다 화면이 한 번씩 튀었다**(특히 mermaid가 있는 문서).
- **원인**: `<Markdown components={{...}}>` 처럼 매핑 객체를 JSX 안에서 만들면 렌더마다 **컴포넌트 타입이 새로 생긴다.** React는 타입이 다르면 갱신이 아니라 **언마운트→재마운트**를 하므로, 미리보기 트리 전체가 새 DOM으로 갈린다. mermaid 블록은 비동기로 SVG를 주입하므로 **높이 0 → 다시 그려짐**을 반복했다. 방아쇠는 `ViewerPanel`의 **10초 잠금 하트비트**(`setLock`)였다 — 내용이 안 변해도 setState는 일어난다.
- **결정**: 매핑·플러그인 배열은 **모듈 최상단 상수**로 두고, `MarkdownPreview`는 `memo`로 감싼다.
- **회귀 방지**: "같은 text로 다시 렌더하면 DOM 노드가 **동일해야 한다**"를 단위 테스트로 고정했다(`MarkdownPreview.test.tsx`). 고치기 전에는 이 테스트가 실제로 **실패**했다.
- **일반화**: 주기적 setState + 무거운 자식 조합에서는, 버벅임의 원인이 "렌더가 느려서"가 아니라 **"재마운트라서"** 인 경우가 많다. 프로파일링 전에 *타입 동일성*부터 확인한다.
